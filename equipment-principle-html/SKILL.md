# 设备原理交互演示

以经过核验的原理基线驱动结构与动画，以用户选定的图片驱动风格。首要目标是让受众看懂过程和因果：输入从哪里来、经过什么、发生什么变化、由谁驱动、最后到哪里去。需要新设备视觉参考时由用户在外部生图并选图；输出提示词不代表已经生成图片。用户已接受 HTML 模板或参考图并要求直接制作时，沿用该选择，不重复要求生图。

## 固定界面模板

按用户明确偏好，今后页面沿用“活塞式压缩机.html”的五区结构。先读取 [fixed-layout.md](references/fixed-layout.md)，从 [equipment-demo-shell.html](assets/equipment-demo-shell.html) 开始制作。保留顶部主题栏、左侧原理面板、中央演示区、底部播放区和工具栏；按需求替换 2D/3D 设备动画、原理内容及设备专用控件。不得自动改为其他页面结构，除非用户明确要求。

按用户明确偏好，默认仅面向电脑端制作和验收；不主动做手机适配、触屏专用交互或手机尺寸测试，也不因手机效果延迟交付。只有用户明确要求手机端时，才将相关实现与测试加入范围。电脑端仍须检查目标分辨率及常见低高度窗口的可读性。

## 三个用户确认节点

1. 需求确认：集中确认设备与演示重点、2D/3D、视觉精细程度及原理深度。给出推荐和理由；核心选择未确认时可整理原理基线，暂不输出正式提示词。
2. 视觉参考选择：已确认的固定 HTML 模板可直接沿用；只有需要新的设备图像参考时，才由用户上传并选定图片。“就用这张”即满足确认。多图未指定时询问选哪张；无法访问图片时请用户提供可读取图片，不假装已看图。
3. 最终验收：先交付经过验证的可运行 HTML，再询问修改意见，不作为制作前的额外批准。

沿用已明确提供的选择，不重复询问。技术审核、提示词修订、编码、测试与修复自行推进；已选图片审核通过后直接制作。关键资料不足、需求冲突、范围扩大或必须由用户决定的取舍才额外询问。用户明确修改流程时尊重其选择，但不能把未核实内容标为已核实。

## 1. 需求与原理基线

读取 [requirements-and-fidelity.md](references/requirements-and-fidelity.md)。提取已有信息，只询问关键缺项。视觉细节和原理深度分开确认，不把精美材质当作工程精度。

在任务输出目录建立 project-state.md，记录设备、已确认选择、原理资料、部件、连接、阶段、未知项、图片版本、当前阶段和下一步。跨轮恢复时读取记录，用户最新明确指令优先。

依靠用户资料或可查证的权威来源建立原理基线，记录文档页码、图号或 URL。通用示意与特定型号分清；关键结构或控制关系未知时请求资料，或取得用户同意采用通用示意，不编造。

## 2. 提示词与选图

此阶段适用于用户需要生图选设备风格的任务。用户已确认参考模板并直接要求制作时，记录参考来源及结构依据后进入 HTML 制作；对收到的图片仍须如实审核。

读取 [image-prompt-template.md](references/image-prompt-template.md)，输出完整可复制提示词，保存 image-prompt-v1.md。风格未定时提供少量可替换风格描述，不改变设备原理。

提示用户生图后上传选中图片，等待图片，不继续依赖图片的工作。已有明确选定参考图时直接审核，不要求无意义的重新生图。

## 3. 图片审核

读取 [image-review-checklist.md](references/image-review-checklist.md)，对照原理基线输出通过、需修正或无法确认，保存 reference-review.md。完整性只针对确认的演示范围，不要求真实设备每个零件。

需修正时指出位置、问题和影响，交付保留风格的完整新版提示词，保存递增版本并等待新图。无法确认不能当作通过。连续两轮同类问题未解决时，建议换视角、局部补图或补充资料，避免无限重复。

用户明确同意“仅参考风格、结构按资料重建”时，记录此分支及依据，不标记原图通过；原理基线足够后可以制作。默认不擅自跳过审核。

## 4. HTML 制作

先读取 [principle-explanation.md](references/principle-explanation.md)，制定“路径—原因—画面证据”的讲解方案，再读取 [html-implementation.md](references/html-implementation.md)，按其中的项目与技术选型规则决定实现方式。提取设备参考的配色、材质、线条和视角，在固定模板的中央演示区重建可交互部件；外层布局按固定模板保留。不把静态图片加按钮当作完成原理演示。单图不能证明隐藏结构与真实尺寸；近似需说明，不宣称工程仿真。

## 5. 验证与交付

按照 [acceptance-cases.md](references/acceptance-cases.md) 检查讲解清晰度、原理、风格和交互。能运行、会旋转、配色相似都不能替代“过程看得懂”的验收。在真实浏览器打开结果，记录环境、操作及结果；不能进行浏览器验证时明确未验证，不写全部通过。

交付 index.html、必要本地资源、validation.md，说明入口和启动方式。需服务器时提供命令；离线要求须实际断网加载验证。单文件按用户要求和可行性选择。

用户反馈原理不清楚时，按讲解参考中的修订流程定位问题并重新制作，不默认重走需求确认和生图。

最终提供链接、实现范围、主要操作、测试结果和必要局限，请用户验收。未经授权不发布到外部网站。
