# 验证与行为案例

## 固定模板验收

对照 [fixed-layout.md](fixed-layout.md) 检查五区布局，确认 2D/3D 变化没有变成整页改版。原设备专用图表和状态必须替换为当前设备的真实含义，不能保留错误气阀、压力或循环数据。检查角度/时间进度、单步、暂停、缩放、视图、导出及全屏与新动画实际联动，最终页面无未替换的模板占位符。

## HTML 验收

真实浏览器打开交付入口，检查控制台和资源加载，记录浏览器和视口。操作开始、暂停、继续、复位、阶段切换和部件选择，连续切换后仍应一致。三维额外检查旋转、缩放、视角复位与内部可见性。

对照原理基线检查运动、流向、阀门状态与说明。截图比较配色、视角、材质及层次；截图不能替代操作。默认检查电脑目标分辨率及常见低高度窗口（如 1600×1000、1280×720），不运行手机尺寸测试；仅在用户明确要求手机端时补充。离线需断网或阻断外部请求后重新加载操作，不能只搜索无 CDN 字样就判通过。

validation.md 记录动作、预期、实测、修复复测和未覆盖项。区分静态检查、浏览器测试和原理核对，不伪造测试结果。

## 讲解清晰度验收

交付前依据页面实际画面逐项作答，写入 validation.md，不能只以无错误日志或没有横向溢出判定通过：

- 首次打开能否指出输入、关键变化位置及输出？记录对应画面区域。
- 能否从入口沿图中路径跟到出口，并看见关键内部变化？机械或控制设备以其实际过程替代流体路径。
- 能否回答“谁驱动、为什么变化、在什么条件下持续运行”，且文字与动画对应？
- 多视图是否有明确的观察方向和共同部件对应，不靠猜测？
- 是否存在穿墙流动、错误方向、假封闭、无依据的完整绕圈，或把连续过程画成间歇顺序？
- 电脑端关键标签是否实际可读，核心示意是否足够大？查看截图，不仅检查溢出。手机可读性仅在用户明确要求手机端时纳入验收。

自动讲解存在时，真实操作验证推进、暂停冻结、手动选择保持、复位、标签及速度切换。验证关键输入、内部变化和输出确实动态变化；对暂停状态同时检查各关联动画和讲解步骤，而非只检查转子。

这些是页面检查，不等于真实用户理解测试；只有用户实际反馈才能记录为用户体验结论。

## Skill 行为案例

1. 只说做离心泵演示：先确认展示方式及两个精细程度维度，不能直接制作。
2. 已说明 2D、视觉标准、原理详细：沿用选择，只补关键未知。
3. 已选图片关键连接正确，仅中文乱码：HTML 重做标签，不强制重生。
4. 缺关键阀门或接口接错：指出位置并修订提示词，默认不开始制作。
5. 内部被外壳遮挡：判无法确认，不能猜测通过。
6. 用户同意仅参考风格并提供结构资料：记录分支后重建，不标原图通过。
7. 要求精确流量仿真但无参数：请求依据或确认改为定性演示，不编造公式。
8. 要求单文件离线 3D：实际验证打包及离线，不交付 CDN 页面冒充离线。
9. 要求可旋转 3D，参考为等轴测：重建几何，不能给平面图加倾斜冒充。
10. 多图未选或图片不可访问：请求明确选择或可读图片，不编造审核。

11. 页面只有转子旋转、粒子在外围绕圈：即使功能测试通过，也应补齐入口、关键内部变化和输出的可见表达。
12. 主图与轴向小图均正确，但没有中心对应说明：补观察方向及对应标记，不靠观众猜测。
13. 用户说原理不清楚：定位具体表达问题并修订，保留前版，不重复询问已确认设置或强制重新生图。
14. 连续过程的分步教学：切换讲解重点，不能让动画暗示不真实的分段运行。
15. 活塞或电气设备：根据运动、力或信号关系组织讲解，不套用离心泵压差、叶轮或水流粒子。

实际使用记录：离心泵案例第一版被反馈“原理描述不明确”，第二版加强路径、因果、视图对应和内部流动后获“相对可以”反馈；仅说明方向获得认可，不代表完美或工程准确性认证。活塞机构、过滤系统及新增行为案例仍需后续验证。

16. 用户要求沿压缩机模板制作 2D 离心泵：保持五区结构，中央改为二维双视图，左侧用流路及能量说明替代 p-V 和气阀数据，不重新设计外层页面。
