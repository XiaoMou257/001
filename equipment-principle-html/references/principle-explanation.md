# 让工作原理看得懂

## 先建立因果，再决定布局

针对已确认的受众与原理深度，为每个关键过程写出“路径—原因—画面证据”：

| 项目 | 内容 |
| --- | --- |
| 路径 | 物料、流体、热量、力或信号从哪里来，经哪些部件，到哪里去 |
| 原因 | 什么驱动变化，在哪个部件做功、传热、转换或控制；需要什么运行条件 |
| 画面证据 | 哪条路径、哪个动作或状态变化能让受众直接看到这件事 |

这张对应表记入 project-state.md 或任务设计记录，无需新增用户批准。避免只列部件名称和“吸入—传能—排出”之类标题，却没有说明因果。按设备实际原理选择路径类型，非流体设备不强加进水、压差或粒子流。

## 组织讲解

- 在首屏给出直观的过程路线，如“入口 → 处理部件 → 输出”，将必要运行前提放在易见位置。
- 区分过程路径与驱动链。离心泵的液体路线是“进水管 → 叶轮眼 → 叶轮外缘 → 蜗壳 → 出水管”；驱动链是“电机 → 泵轴 → 叶轮 → 液体”。只有确实涉及能量来源时才展示独立驱动链。
- 分步标题优先采用受众要理解的问题，如“为什么会进入”“哪个部件使它变化”“怎样持续输出”。说明按“原因 → 发生的变化 → 结果”展开，并指明正在看哪幅图的哪个区域。
- 分步数量取决于实际过程，不固定三个。文字长度按受众调整，关键解释不能只藏在悬浮提示或很小的附图里。
- 将定性示意、真实动作与定量模拟分清；不编造压力值、效率、流线或控制因果。

## 多视图必须可对应

每个视图注明观察方向和承担的问题。共同部件用一致名称、编号或同步高亮，并明确指出对应关系。例如“侧图入口末端对应正面图中央叶轮眼”。不要让观众自行猜测两个图是否是同一个部件。

关键入口、出口或传动关系不能缩成难辨认的小图。默认只检查电脑端可读性；若用户明确要求手机端，再通过重新排版、放大局部或缩放保证手机关键标注可读。

二维箭头表达不了出入画面时，可增加轴向小示意；使用 ⊗、⊙ 等符号必须解释方向并核对观察视角。参考图只保留合理风格，不照搬错误方向、遮挡或相互冲突的连接。

## 动画必须说明过程

- 不只让设备转动或外围粒子绕圈。需要解释流动时，入口、内部关键变化区和出口都应有可见证据；机械、热工、电气设备用相应运动或状态变化表达。
- 将部件运动方向与介质、信号路径区分。若显示相对运动，注明相对哪个部件，避免将相对轨迹误当绝对流场。
- 路径不能穿过不通流的实体或错误接口。装饰线不能看起来封死开放通道，循环播放不能暗示出口液体瞬间沿不存在的管路返回入口。
- 分布汇入的流动不能误画成所有物料必须绕完整一圈。粒子数、速度和位置无计算依据时仅作方向示意。
- 稳定连续过程的讲解切换只改变观察重点；不要误演成先吸入、再停止吸入传能、最后排出。真实顺序设备则按实际动作时序实现。

## 自动讲解与手动观察

内容较多且适合分步时提供可关闭的自动讲解。默认暂停，用户开始后才运动；讲解时间足够阅读，不能因提高动画速度而强迫加快阅读。用户手动选步骤时停止自动切换，或提供明确的等效控制，避免刚选中就被切走。

暂停冻结所有关联动画及讲解计时；复位恢复初始姿态、步骤、速度和界面状态。切回隐藏页面时不突然跳过多个阶段。减少动态效果偏好下不自动播放。

## 用户反馈“不清楚”时

先检查最可能的原因：缺关键路径、只有动作没有因果、视图无法对应、文字与动画脱节、尺寸太小，或暗示错误的物理过程。依据现有页面找出具体问题，不仅换颜色或增加长段文字。

在已授权范围内直接修订，保留上一版用于对比。通常无需重新确认已经接受的 2D/3D、精细度或风格，也不强迫重新生图。只有设备原理、范围或关键资料发生变化时才补充询问。

## 离心泵案例的适用边界

本次第二版得到用户“相对可以”的反馈，可作为清晰度改进实例，而非工程结构模板或最终物理验证。有效改进是放大轴向入口、明确两图中心对应、展示向外运动、区分液体路线与驱动链，并解释入口压差与蜗壳作用。

不固定套用该案例的颜色、叶片数、旋转方向、出口朝向、两栏布局或讲解秒数。其他设备重新依据原理基线设计。
