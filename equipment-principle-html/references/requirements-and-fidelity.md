# 需求与原理基线

提取设备名称、型号、受众、演示重点、资料与运行环境。不要机械输出长问卷，只集中询问影响决策的缺项。

| 等级 | 视觉细节 | 原理深度 |
| --- | --- | --- |
| 基础 | 简化几何和主要轮廓 | 输入、过程、输出 |
| 标准 | 主要部件、剖面、材质区分 | 部件作用与完整阶段 |
| 详细 | 更多内部细节与装配关系 | 有依据的控制联动、异常工况和参数关系 |

两个维度独立选择。推荐起点为视觉标准、原理标准，仍需用户确认或已有选择支持。真实尺寸、公差、性能曲线和定量模拟需额外资料依据。

2D SVG 适合管路、阀门、流程及简单运动；空间装配、多轴关系和观察角度影响理解时推荐 3D。需要空间结构与系统流程时可组合。等轴测平面画法不称为可旋转的真 3D。解释教学价值与运行负担，不把 3D 当作默认升级。

确认示例：“建议采用 2D 剖面，视觉标准级、原理标准级，重点演示流向和部件作用。请确认或告诉我要修改的项目。”已答项不再问。

project-state.md 至少记录：
- 范围：通用类型或具体型号、演示重点。
- 资料：页码、图号或链接及支持的结论。
- 部件：稳定 ID、名称、功能、是否必须展示。
- 连接：起终点、接口、方向，区分介质与控制连接。
- 阶段：名称、部件状态、允许动作、对应说明；区分真实工作时序与仅用于教学的观察步骤。
- 讲解基线：运行前提、输入到输出的路径、驱动或能量来源、关键因果，以及对应的画面证据。
- 多视图关系：各自视角、共同部件和对应标记。
- 参数：单位、范围、关系依据；动画速度不标为真实转速。
- 不确定项和解决方式。
- 已确认选择、图片版本、审核结论、当前阶段及下一步。

默认中文、仅电脑端演示，不主动询问或增加手机适配。用户明确提出离线、单文件、手机端等影响架构的要求时记录并落实；不擅自假定需要精确仿真。
